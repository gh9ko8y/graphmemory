## 短版（发群/朋友圈，约 150 字）

做了一个月，开源了：**GraphMemory**，一个双时态 AI 记忆系统。

普通记忆库只会"存 + 查"。它多做了三件事：
1. **会忘**——六变量衰减模型（意义/细节/检索难度/情绪/巩固/干扰），旧记忆不是删除，是降级成"照片式片段"；
2. **会老**——时间梯度：1 天的事很清楚，半年前的事只留个轮廓；到期自动清理；
3. **会变**——"他 26 岁"不会永远 26 岁：存出生锚点，检索时实时算年龄；"答应周六去海边"到日子变成待确认。

MIT 开源，Neo4j + PostgreSQL + Redis，带 MCP server，任何 AI 代理都能接：
https://github.com/gh9ko8y/graphmemory

## 长版（知乎/公众号/技术帖）

### 为什么要做

现在给 AI 加记忆，主流做法是"文本切块 → 向量化 → 检索 Top-K"。这解决的是"找得到"，但没解决三个更本质的问题：

- **时间**：三个月前的"我喜欢下雨天"和昨天的"我喜欢晴天"，向量库里权重一样。人不会这样。
- **遗忘**：所有记忆永久等权，噪音越积越多，检索越来越不准。
- **变化**："他今年 26 岁"明年就错了；约定好的事过期了也不会被清理。

我们把这些当成第一性问题，做了一个**双时态（bitemporal）+ 六变量衰减**的记忆系统：GraphMemory。

### 它是怎么想的

**1. 双时态：事实有两个时间轴**

每条记忆同时记录：
- **有效时间**：这件事在现实世界里什么时候成立（valid_from / valid_until）
- **记录时间**：我们什么时候知道它的（tx time）

所以能回答"**当时**是什么"和"**后来**改了什么"，而不是只有"现在是什么"。

**2. 六变量：遗忘是降级，不是删除**

每条记忆有六个维度：S(意义) / D(细节) / R(检索难度) / E(情绪) / C(巩固) / I(干扰)。

时间流逝时，D 缓慢下降、R 缓慢上升——直到某天它淡出成一段"照片式片段"：**还记得有这么件事，但细节模糊了**。原文账本（episodes）永远保留，可追溯"当时到底说了什么"。

**3. 时间梯度：不同年龄的记忆，清晰度天花板不同**

| 年龄 | 细节上限 D | 检索门槛 R |
|---|---|---|
| 1 天 | 0.85 | 0.31 |
| 7 天 | 0.48 | 0.40 |
| 1 个月 | 0.04 | 0.80 |
| 3 个月+ | 0.00 | 1.00 |

配合同样的"口径"梯度：旧事不能说成"我记得清清楚楚"，只能说"我记得好像是"。

**4. 时效性：到期的东西不该继续装"现状"**

写库时自动分类并设置有效期：临时状态 1 天、动作 3 天、事件 7 天、承诺 10 天、普通事实 14 天、偏好永久、身份陈述 3 年、不可更改事实永久。有明确日期的约定不设 TTL，到日子进入"待确认"，确认后才定时效。

**5. 动态年龄：年龄要随时间增长**

"用户出生于 2006-02-08"存的是出生锚点，不是"20 岁"。2028 年问就是 21 岁，2030 年问就是 23 岁——不会把两年前的快照当现状。

**6. 竞争检索：不是"最相似"，是"最该想起来"**

排序 = 激活 × 匹配 × 资源适配，配合相对阈值和 Top-K。被检索命中会反向巩固记忆（用进废退）。


### 论文收敛出的 4 条硬结论

设计不是拍脑袋，是把 17 篇记忆/神经科学论文的约束翻译成工程结构：

| # | 结论 | 论文依据 | 工程落点 |
|---|---|---|---|
| 1 | **存储 ≠ 检索**：记忆还在，但可能取不出来 | A04 沉默印迹 · C10 PV+ 读出抑制 | `silent` 状态 + `readout_gain`；检索不到 ≠ 该删 |
| 2 | **写入要挑时机**：只有显著事件开写窗口 | C10 SST+/VIP+ 写窗口 · C09 沉默候选池 | 显著性触发 + 候选池，不是全部都记 |
| 3 | **检索是竞争，不是 top-k**：谁能说话由上下文门控 | C09 容量 46× · Zhang2026 与门 | 分片 + 簇内 WTA + 乘法门 |
| 4 | **遗忘是功能**：全局下调 + 回放巩固，重要的保护 | B05–B08 replay · A03 系统巩固 | 夜间 replay + downscale，S 高者衰减更慢 |

> 一句话：**不是复刻大脑，是抄约束——容量 / 门控 / 分离 / 巩固；每条都能单独测、单独回退。**
**被测过的数据**：

- **事实粒度实验**：同样的语料，原文直接检索 R@1 约 0.55–0.63；先结构化抽取成事实再检索 **0.84–0.86（+53%）**——说明记忆系统的瓶颈在"写侧结构"，不在"检索算法"。
- **合成数据 4,992 条**：向量检索 R@1 0.718，竞争检索 0.790，混合检索 1.0。
- **真实场景**：在一个 QQ 群聊机器人上跑了 4 个月真实对话，用于上下文压缩后，单轮缓存读从 ~100 万 token 降到 **13 万（-86%）**。

### 怎么用

```bash
git clone https://github.com/gh9ko8y/graphmemory
cd graphmemory
cp .env.example .env      # 填数据库密码 + LLM/Embedding key
docker compose up -d
pip install -e .
psql ... -f scripts/init_db.sql
uvicorn graphmemory.main:app --port 8000
```

自带 MCP server，任何支持 MCP 的代理直接接：

```json
{ "command": "python", "args": ["mcp_server.py"],
  "env": { "GRAPHMEMORY_BASE_URL": "http://127.0.0.1:8000/api/v1/memory" } }
```

工具包括：`add_memory` / `search_memory` / `memory_stats` / `get_timeline` / `list_facts` / `memory_dedupe` / `memory_forget` 等 11 个。

### 它不是什么

- 不是端到端产品：需要你自己的 LLM、Embedding 和业务接入；
- 不是"更大更强的 RAG"：它关心的是**记忆随时间的变化**，不是把更多文档塞进上下文；
- 目前偏中文场景（时间表达、年龄口径、承诺识别），英文支持可以贡献 PR。
